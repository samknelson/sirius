# Mask Mode exposure table

Part of the [approval audit](807-mask-mode-audit.md). **All treatments below are proposed, not implemented.**

## Reading the table

- **M** = semantic server-side mask; **B** = refuse/withhold server-side while ON or state unknown; **R** = retain approved non-person fields/routing keys; **G** = explicit limitation needing approval.
- **Bypass** means no privacy formatter protects the payload. A shared date/phone/name/HTML formatter or sanitizer is not a masking boundary. **SSN-format** means the existing shared formatter is used but returns the full number.
- File paths plus function/route/component names are source anchors; line numbers are included for particularly important findings. Paths refer to this audit's source snapshot and can move. `:id` stands for an internal route key unless otherwise noted. A route family denotes all its read, mutation-result, error and nested output contracts, not a claim that every endpoint returns the same fields.
- Every worker tab also inherits worker/contact API requests and headings from `WorkerLayout`; tab-specific payloads are **additional**, not replacements. Unverified optional/dynamic contents are B/G, never assumed safe.
