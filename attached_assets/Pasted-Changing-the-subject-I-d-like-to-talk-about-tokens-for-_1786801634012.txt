Changing the subject, I'd like to talk about tokens, for generating dynamic messages. 

Here are some examples:

[global.date] => Saturday, August 15, 2026
[global.date(format="y-m-d")] => 2026-08-15
[contact.field.birth_date(format="y-m-d")] => 1970-01-01
[contact.field.birth_date.ago] => 56 years 7 months
[worker.contact.field(name="display_name")] => Whatever Whateverson
[worker.contact.address(primary="true").field(name="street")] => 1926 Jupiter St
[employer.contact(type="overlord").address(primary="true").field(name="street")] => 226 whatever street
[worker.contact.address(primary="true").mailing] => 1926 Jupiter St., Beacon, NY 12508
[sitespecific_t631_job_interviews.field(name="status")] => Accepted
[worker.sitespecific_bao_benefit_history] => [A custom block of HTML, generated by querying WMB records for a worker]
[worker.employer(primary="true")] => [Name of the current employer, generated by querying hours data]
[worker.dump(format="html")] => [Outputs an HTML-formatted dump of all the fields in the worker object]

Here's the architecture I'm thinking.

1. A new plugin kind, called "token", with lots of new plugin types. Some are generic, some are component or site specific.

2. The wrapper exposes a method like "expandTokens" (I'm open to suggestions on the naming), which replaces all the tokens in a text string.

3. For each token, we call a function like "evaluate(token, context)". The token tells us which plugin to execute; the context tells what objects and computations to use.

I'm imagining that context has a specific key, called "entity", which holds the "main" entity that the token is evaluating. So:

evaluate(employer.contact(type="overlord").address(primary="true").field(name="street"), [employer => [Employer Object]])
The "employer" plugin simply finds the appropriately named object in the context or the entity, updates the context, and calls the next plugin

evaluate(contact(type="overlord").address(primary="true").field(name="street"), [employer => [Employer Object], entity => [Employer Object]])
The "contact" plugin finds the appropriately named object in the context or the entity. In this case, since there's an entity set, it runs a database query to search for the contact of type "overlord" associated with the "entity". Then it calls the next plugin:

evaluate(address(primary="true").field(name="street"), [employer => [Employer Object], contact => [Contact Object], entity => [Contact Object]])
The "address" object looks for an address in the entity, running a query to find the primary address. It calls the next plugin:

evaluate(field(name="street"), [employer => [Employer Object], contact => [Contact Object], address => [Address Object], entity => [Address Object]])
And "field" simply returns the value of the given named field in the entity.

Note that we might pass in various context variables. For instance, we might specify [worker => [Worker Object], employer => [Employer Object]]. In that case, we could evaluate both [worker.field(name="display_name")] and [employer.field(name="name")].

What do you think of this framework? Am I on the right track?
