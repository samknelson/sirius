**The problem.** We assumed we could finish the migration on the rehearsal branch and then either promote it to default or copy it into `production`. Neither is clean:

- Snapshots, scheduled backups, and point-in-time restore are **root-branch-only** in Neon. Child branches have none of them. We can't run a HIPAA system with an append-only financial ledger without PITR.
- A child branch cannot be promoted to root. There is no metadata-only fix — getting data onto a root branch requires a physical copy.

So the data has to end up on `production`. Two ways to get it there:

| | **Option A — `pg_dump` rehearsal → `production`** | **Option B — run the final migration against `production` directly** |
|---|---|---|
| Rehearsal branch | Source of truth; deleted after | Stays a rehearsal branch; discarded |
| PHI dump file at rest | Yes — full extract, needs compliant host + secure deletion | No |
| Role / sequence / extension reconciliation | Required | Not required |
| Requires migration be fully reproducible from scripts | **No** | **Yes** |
| Storage during transition | Two copies | One |

**What decides it:** whether the migration is reproducible from scripts alone. If everything that shaped the rehearsal branch lives in loader code and migration files, Option B is cheaper and safer. If there are manual fixes on that branch that never made it back into code, Option B silently loses them and Option A is the only choice.
