name: Token plugin framework
description: Chained token ({{contact.address(primary="true").field(name="street")}}) plugin system conventions and gotchas.
---

- REVERSED (2026-08-15 by user decision): legacy flat token ids ({{contact.firstName}}) are now intentionally INVALID — no aliasing, old templates break by design. Fields are read generically via one `field(name=…)` leaf (inputTypes `["*"]`); no PII allowlist (template authors are privileged); derived data = relation segments (worker.bargaining_unit.field(name="name")); field names validate against the live Drizzle schema (per-entity field catalog shipped to client), raw-string fallback for open entity types. Entity plugins resolve `{kind,row,table?}` full rows; FK values auto-render referenced `name` column.
- Drizzle hazard: interpolating `${table.col}` inside a `sql``\` fragment used in `.select({...})` renders an UNQUALIFIED bare `"id"` — correlated subqueries silently mis-correlate and return NULL. Spell correlations as literal qualified identifiers (`"workers"."id"`).
- Audience gating is FAIL-CLOSED: a plugin declaring `metadata.audiences` resolves as missing unless the eval context carries an allowed audience. Delivery paths pass `audience: "email"|"sms"|"inapp"|"postal"`; preview/coverage intentionally pass none and degrade to defaults.
  **Why:** review flagged that gate-only-when-audience-present silently leaks restricted data everywhere.
  **How to apply:** any new render call site must decide its audience explicitly; don't "fix" empty output by removing the gate.
- Evaluator must enforce the same arg contract as shared `validateChain` (unknown args rejected server-side), or warnings/coverage disagree with send behavior.
- Standalone tsx scripts exercising the token system must import `storage` from `server/storage/database` (NOT the `server/storage` barrel) and run from inside the workspace, else barrel init cycles / module resolution break.
- Token-templated notifiers: dynamic-output `event` root advances chain type to the resolved entity's kind; bulk-messaging spec builder must EXCLUDE dynamic roots (else authors see tokens that can never resolve there). A notifier must have templates or getMessage — assert at registration or a misconfigured plugin silently sends nothing.
- Sanitize rendered email HTML AFTER token substitution (allowlist, not just value-escaping) — a token used as an entire href can resolve to an unsafe scheme, and direct API writes bypass the rich-text editor. In-app link templates must be enforced as same-app relative paths both at save time and after rendering (alert UIs window.open non-relative links → stored XSS vector).
- Template-editor default placeholders must be computed with the same config data dispatch uses (defaults can vary per config field), or "blank = default" is misleading in the editor.

**Payload-snapshot event entities:** when the event's row is deleted by delivery time (settlement delete, fore removal) or the payload identifies no row (status transitions), build the event TokenEntity as a snapshot from the payload (`{id, fk fields, value fields}` + the real drizzle table). Merge payload-only discriminators (operation/action) onto the row via a declared `entityFields` extra on the descriptor so one default sentence stays grammatical for all variants ("was created/updated/deleted"). FK columns still auto-render referenced names from a snapshot row.

**Default templates must preserve legacy display semantics:** converting a notifier to templates may not regress its default output (raw `not_available` vs "Not Available", raw amounts vs "$100.50", lost title fallbacks) — completion review rejects that. Keep the old label maps/formatting as derived display fields merged onto the event entity (statusLabel, amountDisplay, operationPhrase, displayTitle in the relation loader), declared via entityFields; raw fields stay available. This is not a "bespoke token" — it lives in the notifier/entity loader like the old getMessage did.

**Token-composing UIs must enforce the shared grammar:** any picker/editor that builds a chain client-side has to import the shared depth cap and stop offering deeper children (a longer chain parses as invalid and delivery ignores it), and must never insert an unfinished placeholder segment — an open-field placeholder needs a real required `name` argument so the picker asks for it and emits `field(name="…")` complete. Argument drafts must be anchored to the chain they were opened under (and cleared on navigation/search), or Apply builds the segment under whatever parent the walk moved to.
